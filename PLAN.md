# FencingCoach — Reliability & Effectiveness Rework

A phased plan to rework the app so it is **reliable** (data/computations you can
trust) and **effective** (coaching output that's grounded and useful). Derived
from a full codebase review + requirements interview.

---

## Locked decisions

| Area | Decision |
|---|---|
| **Goal** | Rework for reliability + effectiveness; make it trustworthy enough to depend on |
| **Trust chain** | Garmin parsing → computed numbers → LLM quality (fix in that dependency order) |
| **Garmin data** | No ground-truth payloads available → harden parsers defensively + **plausibility validation** + surface gaps via a **data-coverage dashboard + diagnostics endpoint** |
| **Readiness** | **Garmin `training_readiness` is the source of truth**; **neutral when missing** (no modifier that day); delete the custom composite scorer |
| **Calorie targets** | **Garmin-measured expenditure** (rolling avg), formula only as fallback |
| **Day-type** | **Configurable weekly schedule** (single source) + reconcile with logged activities via a **fixed activity-type mapping** (MMA→fencing) |
| **Nutrition LLM** | **Confirm-before-save**, never persist silent zeros, flag low-confidence |
| **Coach** | **Transparency (view context snapshot) + grounding discipline + streaming** |
| **Migrations** | **Clean autogenerated baseline matching ORM, reset DB**, real autogenerate going forward |
| **Long-term memory** | **Generate summaries, keep all raw data** (disable destructive purge) |
| **Auth** | **Remove entirely** (single user, Tailscale-only) |
| **Quality gates** | **Tests + GitHub Actions CI + ruff + mypy** |
| **New features** | Fencing-session analysis · Visible readiness-guided auto-deload · Auto-generated morning brief |

**Caveat (assumption):** removing auth assumes the backend is reachable **only**
via Tailscale, never LAN/public internet.

---

## Findings that motivated this plan

**Redundancies / dead code**
- `services/llm.py` — self-labeled DEPRECATED, unused.
- `services/nutrition.py` — superseded by `agents/nutrition.py`; dead.
- `services/mealplan.py` + `services/brief.py` still call the old `get_llm()` while
  `agents/mealplan.py` + `agents/brief.py` exist — half-migrated, inconsistent.
- Duplicated `strip_think_tags` and `_extract_json` across modules.
- Alembic is a no-op: `0001` runs `Base.metadata.create_all`, `0003` uses
  `CREATE TABLE IF NOT EXISTS` with a divergent `usda_foods` schema that never
  applies. Real schema = ORM only; changes to existing tables won't migrate.
- Summarization worker never deployed (not in `docker-compose.yml`) → the
  "Long-term summaries" context section is permanently empty.
- Frontend: unused `framer-motion`, unused Radix `progress/tabs/tooltip`, two
  competing design systems (editorial vs brutalist).

**Bugs / risks**
- `readiness._score_load:166-173` — dead `db.scalar` acute-load query, result discarded.
- Timezone inconsistency — Garmin sync uses `ATHLETE_TIMEZONE`; readiness/targets/
  nutrition use server-local `date.today()` (UTC in container). "Today" can disagree.
- Redundant readiness signal — custom composite vs Garmin `training_readiness`,
  never reconciled.
- Day-type "upgrade from activities" checks for `"fencing"` but Garmin logs fencing
  as MMA/martial_arts → correction silently never fires.
- Nutrition estimate failure persists `kcal=0` → pollutes totals + remaining-target math.
- Frontend has no auth guard / no logout; errors swallowed to empty states.
- `DEFAULT_WEIGHT_KG = 89.0` while the docstring says 80; weight drives all targets.

## Phased implementation (ordered by dependency)

### Phase 0 — Foundation & cleanup (unblocks everything)
- Remove auth end-to-end: delete `api/auth.py`, `core/security.py`, `CurrentUser`
  deps on all routers; frontend: delete `login/page.tsx`, token logic + auth event
  bus in `lib/api.ts`, login link in sidebar. Drop `APP_*` env vars.
- Delete dead code: `services/llm.py`, `services/nutrition.py`; finish agent
  migration so `mealplan`/`brief` use `agents/*` (then remove their `get_llm` deps).
- New **`services/activity_types.py`** — one canonical mapping (Garmin type →
  fencing/gym/rest/cardio), reused by day-type, readiness, context, fencing analysis.
- Fix **timezone**: replace bare `date.today()` in readiness/targets/nutrition/
  training with `ATHLETE_TIMEZONE`-aware "today."
- **Migrations reset**: delete `0001–0003`, generate one clean baseline from ORM;
  reconcile `usda_foods` ORM/DB divergence.
- Config cleanup: align `docker-compose` full-sync days with frontend (365 vs 30),
  remove commented cruft.

### Phase 1 — Garmin data integrity
- Rewrite `persist_day` extractors with multi-key-path fallbacks + **plausibility
  bounds** (reject HRV=0, sleep>16h, etc.), logging structured warnings per
  missing/failed field.
- Persist per-day **extraction coverage** (which metrics parsed) + last-successful-
  value tracking.
- **`GET /diagnostics`** endpoint: per-metric last value, date, N-day coverage,
  staleness flags.
- Frontend **data-coverage panel** on Garmin/dashboard ("HRV hasn't parsed in 6 days").
- Fixtures + tests for parsers using synthetic Garmin-shaped payloads.

### Phase 2 — Computed numbers
- Readiness: consume Garmin `training_readiness`; map 0–100 → red/amber/green bands;
  **neutral when missing**; delete `_score_hrv/_sleep/_body_battery/_load/_rest`
  composite (keep acute:chronic load + rest as *separate advisories* if useful).
  Remove the dead `db.scalar` at `readiness.py:166`.
- Targets: maintenance = rolling-avg Garmin total kcal; formula fallback; keep
  protein/carb periodization; fix `DEFAULT_WEIGHT_KG` comment/const mismatch.
- Day-type: read schedule from config/profile; reconcile with activities via new mapping.
- Tests for target math, band mapping, day-type.

### Phase 3 — LLM trust
- Nutrition: split into **`POST /nutrition/estimate`** (no persist, returns
  macros+confidence) → review/edit → **`POST /nutrition/log`** (persist). Hard-fail
  loudly instead of writing zeros; flag low-confidence in UI.
- Coach: **stream** responses (SSE); add "what the coach saw" context expander
  (surface `build_context` output); strengthen grounding prompt + validator that
  flags fabricated numbers; sane timeouts/retries.

### Phase 4 — Workers & long-term memory
- Add **summarization worker** to `docker-compose` (generate weekly/monthly;
  **purge disabled**).
- **Auto morning brief**: scheduled brief generation so it's ready each morning.
- Garmin worker: reconcile sync-window constants, keep backoff.

### Phase 5 — Features
- **Fencing-session analysis**: per-session HR zones / duration / load trends from
  mapped activities.
- **Visible auto-deload**: surface when/why today's session was adjusted, tied to
  Garmin readiness band.

### Phase 6 — Quality gates (continuous)
- Commit `[tool.ruff]` / `[tool.mypy]` / pytest config; GitHub Actions running
  pytest + ruff + mypy on push; expand coverage alongside each phase.
